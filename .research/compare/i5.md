## Description

`parseArgv` throws a `TypeError` for option names that exist on `Object.prototype`, such as `--constructor`, `--__proto__`, `--toString`, `--hasOwnProperty` and `--valueOf`. The parsed args object is a plain object, so `args[key]` finds the inherited member and `endOption` calls `.push` on it. A user who types one of those names gets a stack trace instead of an "unknown option" message.

## Steps to reproduce

```js
import { parseArgv } from 'clibuilder/esm/invocation/argv.js'
parseArgv(['node', 'cli', '--constructor', '1'])
```

Or run any clibuilder-based command with `--constructor 1`.

## Expected

The option is handled like any other unknown option (for example `--name`, which returns `{ _: [], name: ['1'] }`).

## Actual

```
TypeError: args[key].push is not a function
    at endOption (esm/invocation/argv.js)
```

The same happens for `--__proto__`, `--toString`, `--hasOwnProperty` and `--valueOf`.

## Environment

- clibuilder 12.1.0
- Node.js v26.7.0, Linux x64

## Notes

In `endOption`, `if (!args[key]) args[key] = []` is false for inherited members. Building the args with `Object.create(null)`, or checking `Object.hasOwn(args, key)` and avoiding `__proto__` as a key, would fix it. A `__proto__` key also needs care so that assigning it does not change the object's prototype.
